# 查找论文

用户已给出论文名称、链接或研究方向时直接开始检索，不以记忆中的推荐列表代替实际搜索。方向不明确、同名论文无法区分，或用户的选择影响下一步时，调用 `ask_user` 给出简短选项并等待回答；已有明确要求不重复确认。

1. 优先调用 `web_search`。它复用当前模型供应商的原生搜索与凭据。当前接口不支持时，使用原生命令，通过 curl、PowerShell 或 Python 请求 arXiv、Crossref、OpenAlex 等公开接口或论文官网。鉴权、限流和网络错误按实际原因处理，不声称检索成功。
2. 用实际来源核对标题、作者、年份、版本与论文地址。优先作者官网、官方仓库、出版方和预印本页面；回答提供可点击的来源链接。
3. 指定论文的“找来／打开／阅读／翻译”包含获取原文；只要求推荐或比较时先给候选，使用 `ask_user` 让用户点选需要获取的论文。宽泛的“找几篇”先检索真实候选并让用户选择，不停在一段泛泛推荐后等待用户手动输入。
4. 使用命令工具把选定论文可公开获取的 PDF、TeX 工程、官方 HTML 或其他相关材料保存到当前工作区的合适目录。每篇论文使用一个独立文件夹，相关文件放在一起；路径可按任务组织，不建立登记表。下载后核对实际内容，避免把登录页或报错 HTML 当成 PDF。核对通过后在该文件夹写入 `research.json`：`{"type":"paper","title":"<核对过的标题>","main":"<主 PDF 相对路径>"}`，工作台据此把它列为论文。文件夹已有 `research.json` 时读取并保留原有字段，只补充缺少的字段。获取失败时说明具体原因，不能把来源链接当成已下载成果。
5. 提供已保存原文的工作区链接。用户明确要求在阅读区打开时调用 `open_document`。继续翻译时读取 `paper-translation`，按其来源优先级与执行方式处理。
