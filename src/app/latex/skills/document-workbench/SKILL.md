# 文档与阅读区

通过 `get_workspace_context` 获取当前工作区及项目 TeX 环境路径：`tex.root` 是运行资源目录，`tex.executable` 是 Tectonic 的默认位置，`tex.fonts` 是字体目录；返回路径不代表已经安装。工作区是命令工具的默认目录。使用原生 read/write/edit 和 PowerShell／Bash 组织文件、管理依赖和执行程序。

## 环境与资源目录

只在任务需要时准备环境；直接写入并预览 Markdown 或 HTML 无需安装 TeX。编译前确认所需程序是否可用；已有环境直接复用，缺失时先向用户说明需要安装的环境及联网下载，询问是否同意，得到同意后再安装。本任务中已明确授权的安装无需重复询问；用户不同意时不安装，说明哪些步骤尚未完成。

默认环境包含 Tectonic、基础资源缓存和中文字体。优先执行上下文返回的 `tex.setupCommand` 完整命令数组；也可在 `projectRoot` 所指的项目根目录执行 `npm run tex:setup`。支持 Windows x64、Linux x64/arm64 和 macOS x64/arm64。安装会联网下载程序、字体和宏包，并编译示例；完成后用该环境编译当前工程，核验实际产物。

根据实际工程选择程序和参数；需要 LuaLaTeX、Biber、其他字体或辅助程序时，同样在用户同意后用原生命令和包管理器补充，不要求固定引擎或编译入口。

TeX 工程所需的新增运行资源必须放在 `tex.root` 内，包括下载的安装包、解压目录、程序、宏包、字体、虚拟环境、依赖目录，以及包管理器的缓存、配置和安装临时目录。执行安装前先指定目录，使用程序的本地安装选项和当前进程环境变量；不做全局安装，不向系统目录、用户配置或用户缓存目录写入资源，不修改全局 PATH。OCR 和翻译分别使用上下文返回的 `translation.ocr.root` 与 `translation.root`，安装及使用见 `paper-translation` 技能。

源文件、译稿、图片、PDF 和编译日志属于用户材料，保存在当前工作区的对应工程或输出目录，不放进运行资源目录。以上目录约定由本技能指导执行，应用没有为命令工具增加路径拦截或独立的安装、编译工具。

## TeX 编译

可以直接调用原生程序。使用项目 Tectonic 时，设置项目缓存和字体配置，并让工作目录位于主文件目录。Windows PowerShell 示例（先替换上下文路径，并创建输出目录）：

```powershell
$env:TECTONIC_CACHE_DIR = '<tex.root>/cache'
$env:FONTCONFIG_FILE = '<tex.root>/fonts.conf'
& '<tex.executable>' -b 'https://data1b.fullyjustified.net/tlextras-2022.0r0.tar' -Z 'search-path=<tex.fonts>' --keep-logs --synctex --outdir '../build' 'main.tex'
```

其他系统使用相同的程序参数与进程环境变量。保留 `.log`，需要源文对应时生成 SyncTeX，保持 `\input`、图片和参考文献按原工程解析。

查找包含 `\documentclass` 和 `\begin{document}` 的主文件，读取它引用的源文件、模板和参考文献。先编译原工程以了解依赖和排版，再在独立译稿目录保留工程结构。失败时根据日志排查源文件、依赖或编译器问题，在副本中修复并继续，以本次译稿实际编译成功为验收结果。翻译正文、标题和图注，保留公式、命令、引用键、标签及文件关系。不要用正则替换整套 TeX 语法，也不要为翻译先解析 PDF。

项目 Tectonic 使用 XeTeX 引擎，宏包从上述资源库按需缓存。`--only-cached` 只使用已有缓存；需要下载缺失宏包时，按前面的安装授权执行，已有授权覆盖的按需下载可直接继续。其他引擎按其原生方式管理宏包，安装、缓存和配置仍放在 `tex.root` 内。编译失败后读取日志定位实际错误、修正源文件并重新编译，不能把旧 PDF 当成本次成功产物。

工程自带 `.bbl` 时可沿用已生成的参考文献：在编译副本中将 `\bibliography{...}` 改为 `\input{已有文件.bbl}`，保留参考文献及引用键，再使用正常编译流程生成 PDF。需要控制重跑或更换引擎时，查看原生程序的帮助并选择参数。Tectonic 的 `--pass tex` 只执行 TeX、生成 XDV；它不会完成 PDF 转换。`--reruns` 控制重跑次数。

中文正文使用项目自带字体，无需系统中文字体：

```tex
\usepackage{xeCJK}
\setCJKmainfont{NotoSerifCJKsc-Regular.otf}
```

上述命令的字体搜索参数指向 `tex.fonts`。使用 `ctex` 模板时可设 `fontset=none` 并显式配置以上字体，避免依赖系统字体集。

## 展示产物

成功生成文档后调用 `open_document`，请求阅读区展示结果。它确认文件存在并发出展示请求，不代表浏览器已经渲染成功，也不会代替编译、脚本执行或交互验收；报告中区分实际做过的检查与尚待用户查看的效果。

```json
{"path":"papers/example/build/main.pdf","page":1}
```

`path` 使用工作区相对路径。Markdown 和 HTML 支持 `mode: "preview"` 或 `mode: "source"`；PDF 可用 `page` 指定位置。用户手动打开其他文件后，下一条消息的阅读上下文会更新为用户正在看的文件。工具请求只作用于当前对话所在的工作区页面。

## Markdown

适合重排阅读的材料可输出为 `.md`。支持标题、表格、代码块、相对图片和数学公式；行内公式用 `$...$`，独立公式用 `$$...$$`。保留必要的章节对应和来源信息，复杂 TeX 宏应改成明确的数学表达，不能把任意 LaTeX 工程直接当成 Markdown。

完成后用 `open_document` 打开 `.md` 的预览。

## HTML

工作区内的 `.html` 或 `.htm` 文件可以在中间阅读区打开并执行。使用原生文件工具写入或修改文件，再调用：

```json
{"path":"example/index.html","mode":"preview"}
```

`mode: "source"` 显示源码。

- 页面通过工作区预览地址加载，同目录及子目录的 CSS、JavaScript、图片、字体和数据可使用相对 URL。以 `/` 开头的 URL 指向工作台站点根路径，不是工作区根目录。
- 页面在用户设备的浏览器中运行，与工作台同源，没有额外的 iframe sandbox 限制。可运行脚本、使用浏览器存储、表单、下载和弹窗；全屏已开放。实际可用性仍受浏览器兼容性、用户授权、弹窗拦截及客户端行为影响，不代表拥有操作系统权限。
- 网络请求从用户设备发出。浏览器中的 `localhost`／`127.0.0.1` 指向用户设备，不能据此访问运行工作台的另一台电脑。跨域接口需满足 CORS，HTTPS 页面访问 HTTP 资源仍受浏览器限制；接口鉴权和连通性需要实际确认。
- HTML 不直接运行服务端程序或读写任意本机文件。需要这些能力时，通过原生命令工具执行，或连接实际可访问的服务接口。工作台没有通用请求代理、页面消息桥接或服务进程托管能力，不应假定已有接口。
- `open_document` 只接受工作区文件路径，不接受 HTTP／HTTPS 服务地址。普通网页地址可在对话中提供可点击链接；外部网站是否允许嵌入由该网站决定。
- 切换文件、源码／预览、刷新或文件更新会重新加载页面，内存状态不保留；浏览器存储与后端数据需由页面按任务需要自行保存和恢复。页面关闭与后端进程停止是独立的。
